# Inherited Greenroom decisions

> These decisions document the source foundation. Greenroom Local may supersede cloud-provider and Windows-only decisions as its local runtime is implemented. The original Greenroom repository remains unchanged.

| ID | Date | Decision | Evidence |
|---|---|---|---|
| D-01 | 2026-10-26 | Default speech model is ElevenLabs `eleven_v4`, called directly. `eleven_v3` stays selectable for comparison. | Owner listened to the Slice 0 lab: v4 sounded better than v3. Laughs, sighs, crying, whispers, gasps and out-of-breath lines were rated good. Report not saved, so ratings are the owner's verbal summary. |
| D-02 | 2026-10-26 | Nigerian English accent is not claimed. The test used a default voice, so it measured the voice, not the model. Retest with a library or designed voice. | Owner: the Nigerian line "still bad". |
| D-03 | 2026-10-26 | Kie is secondary until its Turbo voice fix and Dialogue v3 errors are retested. | Kie 422 "voiceId cannot be empty" (fixed in c7589f0); Dialogue v3 "Internal Error" (open). |
| D-04 | 2026-10-26 | Voice design, cloning and a saved voice library go through ElevenLabs and belong to Slice 1 (Cast). Cloning needs a plan that allows it and a permission checkbox. | Owner request. |
| D-05 | 2026-10-26 | VoiceKiller is integrated as a second voice source (key and user id in the Credential Manager). It has no inline sound tags, so tags are stripped and delivery and pace go in its `instructions` field; the UI warns before paying when a line asks for sounds it cannot make. | Owner request; request shapes from the VoiceKiller API docs as read for Soundstage on 2026-10-23. Tested against a fake server only. |
| D-06 | 2026-10-26 | Multilingual: language is a per-character label and a voice-search filter, not a switch sent to the model. Eleven v4 detects the language from the text, so mixed-language lines (Taglish, Pidgin, code-switching) are written as they are spoken and the voice supplies the accent. No accent is claimed until the owner listens. | Eleven v4 lists 90+ languages; docs do not state a v4 language-code switch. |
| D-07 | 2026-10-26 | Every paid action asks first with a character count. Single takes and samples offer a per-session "do not ask again"; batches and voice design always ask. | Owner rule: no unconfirmed spend. |
| D-08 | 2026-10-26 | Engines are where voices come from: ElevenLabs, VoiceKiller, Kie (67 preset voices), Piper (offline) and the owner's own local server. A voice belongs to one engine, so choosing a voice chooses the engine. Offline engines never show a cost sheet. | Owner asked to choose engines and to have local models. |
| D-09 | 2026-10-26 | Piper is the built-in local engine: Windows build downloaded once from its pinned GitHub release (size and SHA-256 checked), voices from the public catalogue (MD5 checked). A local server is accepted only on 127.0.0.1 or localhost. Piper reads plain text, so tags are stripped. Expressive local models (Chatterbox and similar) are reached through the local-server connector until they can be installed in one click. | Piper is small, CPU-only and covers many languages; Chatterbox needs Python and a GPU. |
| D-10 | 2026-10-26 | The Soundstage PRD-002 is not the plan for Greenroom. Greenroom keeps only: script, voices and engines, directing with chips, takes, export, and later an AI Director and music. Video, hardware profiles, a model registry and a timeline are out of scope unless the owner asks. | Owner asked whether the PRD was overkill; it is what made Soundstage feel heavy. |
| D-11 | 2026-10-26 | ElevenLabs plan limits on saving, adding or cloning voices are explained in plain words with the options that still work (premade voices, VoiceKiller, Kie, Piper). | Owner hit an upgrade prompt when saving a voice. |
| D-12 | 2026-10-26 | Direction has three layers on every line: chips (emotion and sounds), a plain-language director's note, and tags typed or inserted into the words. The note is sent as a tag to ElevenLabs, as an instruction sentence to VoiceKiller, and ignored by Kie, Piper and local servers (the app says so). Effort sounds (grunt, strain, pant, wince) are marked untested until the owner listens. | Owner asked how to direct a voice and mark effort such as lifting something heavy. Idea confirmed by the plain-language directing in vois.so and BeeVoice. |
| D-13 | 2026-10-26 | The AI Director uses a Kie text model (`gemini-3-8-flash-openai`, OpenAI-style chat endpoint, per docs.kie.ai on 2026-10-26). It only suggests: the owner reviews and applies, lines already directed by hand are left alone by default, replies are checked against the allowed tags, and nothing is generated or spoken by it. It asks first because it uses Kie credit. | Owner has ElevenLabs, VoiceKiller and Kie keys; only Kie offers text models. |
| D-14 | 2026-10-26 | A project-wide pronunciation dictionary swaps written forms for spoken ones in what is sent, outside [tags]. The script and line text are never changed. | Borrowed from vois.so; names such as Tunde are often mispronounced. |
| D-15 | 2026-10-26 | A script with no `NAME:` lines is read as one Narrator, one paragraph per line. When any speaker line exists, unnamed paragraphs stay stage direction. Voices are chosen on the Script screen as well as Cast, and a Done button is always shown. | Owner typed one plain line and found no lines, no button and no way to choose a voice. |
| D-16 | 2026-10-26 | Every library voice card has a Use this voice for... choice listing the open project's speakers, and shows which characters it is the voice of. Controls may never spill outside their card (selects and inputs are width-capped). | Owner: no way to say use it on a saved voice; a voice dropdown spilled out of its panel. |
| D-17 | 2026-10-26 | Lines are shown as a visual editor by default: words with click spots between them, sounds as colour-coded pills (reactions green, effort amber, voice blue, beats grey, own sounds purple) that can be dragged to another spot or removed, plus a box for a sound of your own. Plain-text editing stays one click away. The stored line is still ordinary text with [tags]. | Owner asked for a way to visually insert sighs and laughs. |
| D-18 | 2026-10-26 | Pro audio: exports default to 48 kHz, 24-bit WAV with Broadcast Wave header and embedded cue markers. Loudness uses ITU-R BS.1770 with a static gain and a true-peak ceiling and no limiter. Stems share one gain so they add back to the mix. Handoff files are a label track, a cue sheet with provenance and an OTIO timeline. See docs/PRO_AUDIO.md. | Owner chose Pro audio as the first milestone toward professional use. |
| D-19 | 2026-10-26 | ElevenLabs source quality is a setting (MP3 128 / MP3 192 / WAV 44.1 / WAV 48) checked against an allow-list in the backend. Plan limits are explained when a higher quality is refused. A 24-bit export of an MP3 take is labelled as not gaining detail. | ElevenLabs docs list the output formats and say 192 kbps needs Creator and 44.1 kHz WAV needs Pro. |
| D-20 | 2026-10-26 | Studio trust is a record and a warning system, not a gate. Takes keep provenance and an audio fingerprint; cloned voices need a consent record to be created; any voice can carry a commercial-use note; owner-entered prices, a per-project budget and a spend ledger give estimates and an over-budget warning that is never skipped. Exports can include a cue sheet with provenance, a production report with an AI disclosure, a rights register and a SHA-256 manifest. See docs/STUDIO_TRUST.md. | Owner chose Studio trust as the second pro milestone. Light-touch by design, since the heavy gating in Soundstage felt restrictive. |
| D-21 | 2026-10-26 | Picture sync: a project can hold one video (path and facts only; the file is not copied). Frame rate is read from MP4/MOV/M4V headers as an exact fraction; other types ask the owner. Lines get optional cues (seconds from picture start, snapped to frames); uncued lines follow the line before, and dialogue may overlap. With a picture, exports can be trimmed or padded to exactly the picture length, WAVs carry a Broadcast Wave time reference, and the cue sheet and OTIO use the picture frame rate and start timecode. Non-drop timecode only. See docs/PICTURE_SYNC.md. | Owner chose Picture sync as the third pro milestone. |

| D-22 | 2026-10-26 | Timeline: lines are moved by setting their cue, so the stored script stays plain. Same-character overlaps crossfade automatically with equal-power curves; every line has small edge fades. Music is imported into the project as a take (copied, not linked) with a source and licence note that goes into the production report. Ducking is computed from the line positions (default -12 dB, 150 ms attack, 250 ms hold, 700 ms release), is deepest-wins and shared by playback and export. No undo in this version. See docs/TIMELINE.md. | Owner chose Timeline editing as the fourth pro milestone. |
| D-23 | 2026-10-26 | Writing a video with the mix uses ffmpeg as a separate program, never re-encoding the picture (stream copy; the original is never changed). Greenroom uses its own copy, downloaded once from the pinned gyan.dev essentials 9.0.2 release on GitHub and refused unless size and SHA-256 match, or else one already on the PATH. The new sound is the first audio track (AAC 320 for MP4, 24-bit PCM for MOV, FLAC otherwise); the original sound can be kept as a second track. Output is written to a .part file and renamed, so a failure never leaves a half-written video. Start timecode of the source is not carried over. See docs/VIDEO_MIX.md. | Owner asked for a video file with the new mix. A pure-Rust MP4 writer was rejected as too large and risky for the gain. |
| D-24 | 2026-10-26 | Timeline undo is scoped to the arrangement (cues, fades, line level, music, ducking) rather than the whole project, so it can never discard takes, text or voices made since. One history per project is kept in memory while the app runs, with quick same-kind changes merged. Saved casts are kept in `casts.json` in Documents\Greenroom, apart from any project; a cast maps character names to voices and is applied by name (case-insensitive), falling back to the same engine and voice name if the voice id changed. Applying a cast costs nothing and only touches characters whose names match. | Owner asked for undo for the timeline and saved casts. |
| D-25 | 2026-10-26 | Music generation uses Suno through the owner's Kie key: always custom mode, versions V6, V6 Mini and V6 Wild only (Kie marks older ones discontinued), limits checked before sending, always a confirmation sheet and a Studio price. Every returned track is saved as an immutable take; the owner chooses which goes on the timeline. Generated music is flagged in the production report with how it was made, and Greenroom does not claim it is cleared for commercial use. The `zip` dependency was upgraded to 9 to clear three advisories. See docs/MUSIC.md. | Owner asked for Suno music via Kie and supplied the docs location. |
| D-26 | 2026-10-26 | The accent sheet makes samples only after one confirmation that shows the whole run's size and cost, saves after each accent, and stores ratings and audio locally. Scores are the listener's; nothing in the app or its reports claims a voice has an authentic accent. Voice faces are generated illustrations seeded from the voice id, not photographs or likenesses; real photos are not used. Each line on Perform can switch voice, and therefore engine. See docs/ACCENT_SHEET.md. | Owner asked for an accent listening sheet, said Make a take was inactive (the character had no voice and nothing said so), could not switch engines on Perform, and found the cards cluttered. |
| D-27 | 2026-10-26 | Calmer screens: each line's direction controls fold behind Direct this line (a summary of what is set stays visible); Find a voice uses the same face-and-name cards as the library and collapses the 84 language tiles once one is chosen; Timeline ducking and Export's handoff and legal options fold away; Home shows project covers (generated waveform art) and a first-run hero; Write shows its syntax as three small examples. Nothing was removed: every control is still one click away. | Owner: cards too cluttered, no visual interest. |
| D-28 | 2026-10-27 | Cut list export is a CMX 3600 EDL (text, non-drop) built from the same plan as the timeline, with record times on the picture's start timecode and source times from each file's start. AAF is not built: it is a binary format that needs a dedicated library and proof in the target programs, so it waits until the EDL and OTIO have been opened in real post software. Levels, fades and ducking travel only as comments in an EDL. See docs/CUT_LIST.md. | Owner asked what is next; interchange was the biggest gap in the readiness list. |
| D-29 | 2026-10-27 | Undo is project-wide and replaces the Timeline-only history. Because takes cost credits, making a take ends the undo history and undo never removes a take or the spending ledger. Versions (copies of project.json, newest 60, also made automatically when saving if the newest is over ten minutes old) go further back, and restoring one is itself undoable. Backups are zips of the project and all takes with a SHA-256 manifest, made daily on open (newest five per project) or on demand; restoring a backup always creates a new project and verifies everything before writing. Backups are not encrypted. See docs/HISTORY.md. | Owner asked for whole-project undo, automatic versions and backups. |
| D-30 | 2026-10-27 | Studio opens with three summary tiles (voices and rights, estimated spend against budget, takes and fingerprints), shows rights as face-led rows, and folds Prices and budget and the take history. Engines are one folded card each with a mark, a one-line description and a status badge, and the sound engine sits with them. Settings keys use the same marks, and the Kie hint no longer says it is only for the Voice lab. Nothing was removed. | Owner asked to declutter Studio and Engines and re-check Settings and Lab. |
| D-31 | 2026-10-27 | Updates use Tauri's updater with a minisign key pair made for Greenroom (public key in the app, private key at %USERPROFILE%\.greenroom\update-key, no password, outside the repository). Greenroom looks for updates at start (switchable) and on request, never installs without the owner pressing the button, and refuses any installer whose signature does not match (tested with a changed byte and a damaged signature). Releases are made by scripts/release.ps1 and published by hand on GitHub: Greenroom never holds a GitHub token. Windows code signing is prepared (GREENROOM_SIGN_THUMBPRINT) but not active because it needs a certificate the owner must obtain. The updater's zip feature is off to keep cargo audit clean. See docs/RELEASING.md. | Owner asked for code signing and auto-update. |
